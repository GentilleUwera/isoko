# Experimental protocol and evaluation model

## Wire representation and identity

A data frame is deterministic, UTF-8 JSON: `{type: "data", packet: {...}}`. Packets contain learner pseudonym, kind, text, creation tick, deadline, risk, gap, dependency IDs, value, final destination and ID. ID is the first 24 hexadecimal characters of SHA-256 over the canonical packet fields excluding ID. Encoding sorts keys and omits insignificant whitespace. Receiver recomputes the ID, rejects expired packets, and inserts accepted packets transactionally with an ID primary key. This hash is an integrity checksum, not authentication.

ACK frames contain `{type: "ack", id: ...}`. Peer identity is carried by the trusted local link/controller. An ACK is generated only after successful receiver storage. Sender records peer receipt durably. A lost ACK causes retries after four virtual ticks; receiver deduplicates. Control RPC framing used to talk to workers is outside the modeled link budget.

Expired data stays on disk for inspection but is not selected or accepted after its deadline. There is no storage-capacity limit or eviction model. A packet larger than a contact budget cannot cross that link because fragmentation is not implemented.

## Routing and processes

Routes are fixed: cloud → relay → learner for content; learner → relay → cloud for responses. The learner process represents a hub containing multiple pseudonymous learners, not separate radios for each learner. Packets at their final destination are not forwarded.

Each worker owns one SQLite connection and database. The controller only sends serialized frames through its impairment model. Scheduling requests run inside the sender node and use local packet and ACK state. Receiver inventory is used by the application and evaluator, not supplied to the scheduling algorithm.

## Candidate scheduler

For packet p and sender's acknowledged peer set K, let C(p,K) be p plus its transitive prerequisites not in K. Reject a candidate if a prerequisite is missing locally, in retry cooldown, cyclic, or expired. Admission requires the sum of serialized data-frame sizes for C to fit the remaining budget.

Assumed packet value:

    u(p) = value(p) × (1 + risk(p) + mastery_gap(p))

Score:

    [sum(u(x) for x in C) / sum(wire_bytes(x) for x in C)]
      × [1 + 1 / (1 + max(0, deadline(p) - tick))]
      × [1 + min(2, max(0, tick - last_attempt_for_learner) / 12)]

For learners never attempted, creation time replaces last attempt. Select the maximum-score closure, transmit prerequisites first, mark all attempts, then repeat until no candidate fits. Lexicographic ID breaks ties. The service-age multiplier is based on transmission attempts; it is not a guaranteed service constraint or proof against starvation. It is disabled by `no_fairness`. `no_dependencies` scores individual packets with the same remaining terms.

This is a greedy heuristic, not an optimal solver. It does not predict future contacts or estimate receipt probability. ACK and data allocation is a fixed protocol rule, not a jointly optimized decision.

## Baselines

FIFO sorts by creation time, EDF by earliest deadline, risk by descending risk, and density by u(p)/wire_bytes(p). All four select individual fitting packets and share expiration, routing, retransmission, accounting and receiving/application behavior. The dependency-unaware baselines may deliver unusable enhancements; the evaluator gives those no useful value until prerequisites arrive. No baseline gets free receiver-state information or free ACKs.

## Automated contact model

48 integer ticks by default. Cloud–relay contacts occur at multiples of six; relay–learner contacts at ticks congruent to two modulo six. The outage suppresses contacts from tick 12 through tick 17. Nodes restart at tick 16. Tick durations are abstract, not calibrated radio seconds.

Each bidirectional contact has 1,024 or 4,096 bytes in the benchmark. Pending ACKs have strict priority; data direction precedence alternates between contact cycles. Every serialized attempted frame—including lost frames—consumes capacity. Admission of a data closure does not reserve future ACK capacity. ACKs that cannot fit wait for another contact; transmitted but lost ACKs are regenerated by duplicate data reception. Duplicate pending ACKs are coalesced.

Loss is keyed by workload seed, source, destination, frame type, packet ID and attempt number. Policies therefore share packet-specific loss draws when corresponding attempts occur. It is not a shared physical fading trace. Data and ACK loss are independent draws and use separately configurable rates. Frame arrivals are delayed one tick by default; a frame successfully emitted remains in flight even if the link later closes. There is no serialization-time-within-contact model, bit-error model, congestion control or wall-clock bandwidth shaping.

The controller retains future arrivals, pending ACKs and synthetic application state in memory. A node restart is tested; a controller crash is not recoverable. The manual `session contact` command uses zero-delay arrivals and immediate ACK attempts after each data group, rather than the automated model's pending-ACK queues; it demonstrates actual durable packet transfer, not benchmark timing equivalence.

## Workload and metrics

Twelve synthetic learners each generate a question, hint and explanation. Hint depends on question; explanation depends on both. Question value is 1, hint .4, explanation .6. Creation ticks are 0–8, deadlines 12–28 ticks after creation, risk/gap independent uniform draws rounded to two decimals. Text repetition changes packet sizes. This is a deliberately limited test workload, not representative educational evidence.

A content packet becomes useful only when it and all its prerequisites have become useful at the learner by its deadline. Usable value sums u over that set. Reach counts distinct learners with useful questions. Automatically generated responses explicitly carry `synthetic: true` and travel through the same reverse route. They do not count toward the forward useful-value metric. Remaining unusable/undelivered packets count against completion; no success is inferred from transmission alone.

Metrics also report response returns, unusable received packets, in-flight frames, pending ACKs and attempted data/ACK/loss/duplicate bytes. Duplicate bytes mean data arriving at a node where the ID already exists. End-of-horizon censored queues are reported rather than silently treated as delivered.

## Test coverage and remaining gaps

Tests exercise lossless end-to-end completion, isolated process/reference equivalence, restart persistence, missing prerequisites, retry cooldown, exact budget fit, zero capacity, complete data loss, complete ACK loss, duplicate idempotence, hash failure, expiration and manual answer round-trip. All policies have deterministic capacity-accounting checks. They do not establish implementation security, BP conformance, real RF behavior or algorithmic optimality.
